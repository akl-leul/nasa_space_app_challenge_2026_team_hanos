## 1. Challenge page (official brief)
Text only, no images. Key points:
- SPHEREx maps the whole sky **every six months** in 102 bands. The tool must let users enter RA and Dec and show a series of images "like a little video".
- Test targets: Barnard's Star, Epsilon Indi B, WISE 0855 (RA 08h55m10.831s, Dec -7d14m42.53s), RW Aurigae, R Draconis.
- Optional considerations (these are our "NASA SUGGESTED" items): easy to update with new releases; display the 102 bands creatively; **"separately add together all the data taken by each of the six detector arrays to improve the signal-to-noise"**; generate spectra on the fly; add or subtract images from different times; let users choose the field of view ("larger fields of view make it possible to track faster-moving sources, at the cost of longer data transfer times"); overlay Gaia or WISE; query by coordinates in the URL "so users can embed it in other websites"; show metadata such as contamination flags; consider Astropy tools and **Aladin (CDS)** for display.
- Background mentions Pluto's discovery and Backyard Worlds (volunteers blinking WISE images).

## 2. IRSA SPHEREx page
Two icons and link lists only. It confirms: releases QR1 July 2025, QR2 Oct 2025, QR2 headers fixed (10 Apr 2026 here; the user guide says 31 Mar), **QR3 Sept 2026, DR1 Nov 2026**. Tools: Data Explorer, MOST, Spectrophotometry Tool, Mosaic Tool, Cutout Tool, Source Discovery Tool. Documents: Spectral Calibrations, Explanatory Supplement, Archive User Guide. Also SPLICES (about 9 million ice-source targets) and 3I/ATLAS spectral images.

### IRSA documentation behind it (read in full)
- **User guide, data releases:** DR1 = Survey 1 and 2 data reprocessed like QR3, plus the **All-Sky Cube**. QR3 = Survey 3 and 4. **DR1 and QR3 supersede QR2; QR2 is no longer searchable** and stays downloadable only until February 2027. QR1 is retired. Timeline figure (`spherex-release-timeline.png`): four full-sky surveys over about two years (Surveys 1 and 2 in year 1, 3 and 4 in year 2). Later: High Reliability Source Catalog V1 Aug 2027, DR2 Dec 2027. So each sky position is visited about once per survey, roughly every 6 months, which is why a time-lapse has only a few epochs per wavelength channel.
- **Citation (required for DR1):** DOI 10.26131/IRSA678 (spectral images) and 10.26131/IRSA679 (all-sky cube), plus the acknowledgement text on the DR1 overview page.
- **Data access:** browsable root `https://irsa.ipac.caltech.edu/ibe/data/spherex/` with folders `dr1`, `qr3`, `qr2`; **SIA2 endpoint `https://irsa.ipac.caltech.edu/SIA?`** with `COLLECTION=` one of `spherex_dr1`, `spherex_dr1_deep`, `spherex_dr1_cube`, `spherex_qr3`, `spherex_qr3_deep`; position syntax `POS=circle+RA+Dec+radius` (degrees). SIA lags about a day behind ingestion; browsable directories, the Data Explorer and TAP see new data first. SIA results include `access_url`, `cloud_access` (AWS S3 bucket `nasa-irsa-spherex`, anonymous), `t_min`, `t_max`, `em_min`, `em_max`, `energy_bandpassname` (for example `SPHEREx-D2`), `s_region`, `obs_id`.
- **Cutouts:** append `?center=RA,Dec&size=DEG` to an on-premises `access_url` (degrees; the tutorial writes the declination with a trailing `d`). Cutout parameter docs: `https://irsa.ipac.caltech.edu/ibe/cutouts.html` (verify). Cutouts keep all extensions and both WCS.
- **Files:** one MEF per detector per pointing (about 70 MB), but **some pointings lack some bands** because quality is judged per band. Folder layout `level2/[Planning Period]/l2b-v[Version]-[Date]/[Detector]/`. Extensions: IMAGE (MJy/sr, ZODI **not** subtracted), FLAGS, VARIANCE, ZODI, **EPSF (DR1 and QR3; 21x21 zones, but detector 3 has 11x41 zones)** or PSF (QR2: 121 planes of 101x101), WCS-WAVE.
- **All-Sky Cube (DR1):** 12,288 HEALPix tiles (order 5, **NESTED**), about 1.8 degrees each, 512x512 pixels at 12.9", 102 channels (6 bands x 17 channels, `index = 17*(band-1)+(channel-1)`), **ZODI already subtracted**, channels 51 and 52 (next to the dichroic) are blank (`BLANKCH`). Extensions IMAGE, NHITS (input pixel count), FLAGS, SPECTRAL_CHANNELS, WCS-WAVE. Helium 1.083 micron and other emission lines cause stripes. The HiPS tree of PNGs is **for visualisation only** (fixed stretch 0 to 40 MJy/sr, low dynamic range). HiPS root `https://irsa.ipac.caltech.edu/data/hips/SPHEREx/spherex_allsky_cube` (a `properties` file), FITS tiles under `https://irsa.ipac.caltech.edu/ibe/data/spherex/dr1/hips5_cube/hips_20261026/Norder5/Dir{(ipix//10000)*10000}/Npix{ipix}_cube.fits`.
- **Calibration products** (browsable, not in SIA): Solid Angle Pixel Map (per detector, 2040x2040, pixel value = solid angle in arcsec squared), Spectral WCS, Spectral Channels, ePSF, Zodi scaling, and others.
- **Spectral calibrations page:** transmission curves at 17, 34, 51 or 68 sub-channels per detector; the files are in detector coordinates and **flipped in x for detectors 4, 5 and 6** compared with sky images.
- **MOST (moving object search):** `https://irsa.ipac.caltech.edu/cgi-bin/MOST/nph-most?catalog=spherex&input_type=name_input&obj_name=NAME&obs_begin=YYYY+MM+DD&obs_end=YYYY+MM+DD&output_mode=Brief` (the keyword table says `outfmt`, the examples say `output_mode`; verify). `catalog=spherex` is supported, as are wise_merge, wise_neowiser, ztf, 2mass and others. Input by name, NAIF ID, MPC string or orbital elements.
- **Spectrophotometry Tool and Mosaic Tool** are GUI forms inside the Data Explorer (tabs Spectral Image Search, Spectrophotometry Tool, Mosaic Tool, Job Monitor). Spectrophotometry: single or multi-object, name by NED then Simbad, coordinates in several frames, optional deep fields, point-source or Sersic model, band and time filters, **jobs take minutes, hours with deep fields**, not for extended sources. Mosaic: centre, size 0.1025' to 300', rotation, pixel size 6.15" to 3600", wavelength range; yields a 102-plane cube. **The tutorial states the Mosaic Tool has no API.** Neither tool has a confirmed programmatic interface, so they are link-outs only.
- **Native pixel scale is 6.15 arcsec** (mosaic minimum pixel size), not 6.2.
- **3I/ATLAS:** SPHEREx observed this interstellar comet in August and December 2025. A VOTable `obscore_3I_Atlas.vot` lists each exposure with the **predicted** comet position (`comet_ra`, `comet_dec`). The comet is extended, so the Spectrophotometry Tool is not recommended.
- **SPLICES:** about 9 million IR-bright ice-source targets; DOI 10.26131/IRSA554.

## 3. SPHEREx tutorial notebooks (six, all figures viewed)
1. **Data overview** (`spherex-intro`). SIA query by position, the 6 HDUs (listed above), the three WCS (main 1-based sky, `WCSNAMEA` 0-based, `WCSNAMEW` spectral). Spectral WCS must be loaded with `WCS(header, fobj=hdulist, key="W")` and `sip=None`. FLAGS bits from the header (`MSKNnnnn`, `MSKDnnnn`): 0 TRANSIENT, 1 OVERFLOW, 2 SUR_ERROR, 6 NONFUNC, 7 DICHROIC, 9 MISSING_DATA, 10 HOT, 11 COLD, 12 FULLSAMPLE, 14 PHANMISS, 15 NONLINEAR, 17 PERSIST, 19 OUTLIER, 20 CROSSTALK, **21 SOURCE (known source, most pixels carry it)**, 22 GHOST, 23 GHOST_FPA, 24 GHOST_EXT, 25 STREAK, 26 BLOOM, 27 SNOWBALL, 28 HALO. Header keywords `HIERARCH L2 N_*` count flagged pixels (these give a ready flag summary). Figure: the wavelength map of detector 1 is a smooth gradient mostly **along image rows** (0.75 micron at the top to about 1.12 at the bottom), so a small cutout covers a nearly single wavelength. The notebook prose says "Detector 2" while the header prints `DETECTOR: 1`; trust the header and the file path.
2. **Cutouts** (`spherex-cutouts`). TAP/ADQL on `spherex.artifact` joined to `spherex.plane` on `planeid`, `CONTAINS(POINT('ICRS', ra, dec), p.poly)`, filter `p.energy_bandpassname = 'SPHEREx-D2'`, order by `p.time_bounds_lower`; the cutout URL is built as `'https://irsa.ipac.caltech.edu/' || a.uri || '?center=RA,Decd&size=DEG'`. **A TAP query took about 20 s** and 84 cutouts took about 0.2 min with 10 parallel workers; some cutouts fail transiently, so retry. The cutout `VERSION` keyword is in the primary header. Figure: 10 M101 cutouts at different wavelengths. They show **hot, cold and flagged pixels** as bright or dark squares, and **cutouts near a detector edge are truncated to different shapes** (one is 60x33 pixels).
3. **PSF** (`spherex-psf`). EPSF table: 441 rows, each a 33x33 ePSF **oversampled by 5**, one per region (about 97x97 pixels), with `XCENTER`, `YCENTER`, `CWAVE`, `CBAND`. For cutouts convert positions: `xpix_orig = 1 + xpix_cutout - CRPIX1A`. Figures: an ePSF image; maps showing the PSF effective area varies from 4.0 to 4.8 across the detector and with wavelength (2.4 to 3.8 micron); two PSFs at different positions look different. **PSF changes with position and wavelength, so compare same-detector, similar-wavelength frames.**
4. **Source discovery** (`spherex-source-discovery-tool-demo`). Cloud access through `cloud_access` JSON (`s3://nasa-irsa-spherex/...`, anonymous). **Unit conversion**: `(MJy/sr) -> uJy/arcsec^2`, multiplied by the Solid Angle Pixel Map in arcsec squared, gives **uJy**. Local background with `sep`; masks from FLAGS; common grid with `reproject`; subtract D2 minus D4 (a colour difference) to find red sources; SExtractor catalogs; spectra.
5. **Mosaic cube** (`spherex-mosaic`). Cube extensions IMAGE, NHITS, FLAGS, SPECTRAL_CHANNELS, WCS-WAVE; conversion `mJy = MJy/sr * 23.5045 * (pixel scale in arcsec)^2 / 1000`. Spectrum by **aperture (radius 20 px) minus an annulus (60 to 100 px)** with Photutils. Figures: the aperture and annulus on the collapsed cube; a 102-point spectrum in mJy with dotted markers for Pa-beta, the 1.6 micron bump, Pa-alpha, Br-beta, PAH 3.3 micron and Br-alpha (visible **offsets between detectors**); a PAH 3.3 micron map built as the on-band channel minus the continuum channels (61, 62, 64, 65 versus 63); a GALEX FUV image with SPHEREx PAH contours overlaid (a cross-survey overlay).
6. **HiPS cube** (`spherex-hipscube`). Programmatic quick-look spectrum at any coordinate with plain HTTP: read `properties`, compute the HEALPix index with `hpgeom` (order 5, nested), download `Npix{ipix}_cube.fits`, extract with aperture photometry. Figures: Science image, **Hits Map** (exposure count, with visible scan stripes) and **Flags Map**; the aperture plot; a spectrum with markers for Pa-beta, H-minus, Pa-alpha, Br-gamma, Br-beta, PAH 3.3, Br-alpha and CO. Stripes appear near bright emission lines and do not affect the Spectrophotometry Tool.

## 4. WiseView (opened live in a browser)
By Dan Caselden and Paul Westin, operated by the American Museum of Natural History. Shows **unWISE time-resolved W1/W2 images** (top) and a **Pan-STARRS** optical context image (bottom), with a left sidebar.
- URL hash parameters (verified): `ra, dec, size` (arcsec), `band` (1 = W1, 2 = W2, 3 = W1+W2 as colour with red = W2, blue = W1, green = average), `speed` (blink interval ms), `minbright, maxbright, linear` (asinh stretch, "linear" is the `a` parameter of `AsinhStretch`), `window` (years, sliding epoch window), `diff_window`, `zoom`, `border`, `gaia` (Gaia DR3 overlay), `invert`, `maxdyr`, `scandir` (separate scan directions), `neowise`, `diff` (difference imaging), `outer_epochs` (skip middle epochs), `unique_window`, `smooth_scan`, `shift` (shift and add), `pmra, pmdec`, and synthetic-object injection (`synth_a_*`, `synth_b_*` with position, W1, W2, proper motion, MJD).
- UI ideas: a large **epoch label** (for example "2014.8 - 2015.3"); an **epoch legend** of `+`, `-` and `.` marks showing which epochs are added, subtracted or unused in the current frame; a **dashed border when the animation loops** so users can tell a real consistent motion from a reset; click to re-centre; click-drag to open a new tab with another field of view; links to LegacySurvey, Simbad, VizieR and nearest Zooniverse subjects; input in decimal degrees or sexagesimal with colons, spaces or h m s letters. Default blink 500 ms, window 0.5 yr, W2, inverted.
- Credit: unWISE (Lang 2014; Meisner et al. 2017) and Pan-STARRS. Do not copy WiseView code or images.

## 5. Gaia at MAST
Gaia observed 27 July 2014 to 15 January 2025, more than a billion stars to magnitude 20; astrometry, G photometry and BP/RP, radial velocities, solar-system objects. DR1, DR2, EDR3 and **DR3 (use DR3)**. Tools listed: ESA Gaia Archive (`https://gea.esac.esa.int/archive/`), MAST Portal, MAST astroquery, CasJobs, VO services. Two images: a **sky map of Gaia star proper-motion trails over the Milky Way**, and a **wavelength-coverage bar from about 3300 to 10,500 angstrom** (optical only, no infrared beyond about 1.05 micron). So Gaia gives positions and motions, not fluxes comparable to SPHEREx. Gaia does not overlap SPHEREx in time, so propagate positions with proper motion.

## 6. NEOSSat (CSA page, tutorial repo and dataset record)
- CSA page: launched 25 Feb 2013, about 800 km orbit, about 100 min per orbit, asteroids, comets, satellites, debris, exoplanet transits; images go to the CSA Open Data Portal and the CADC; images include a 3D model, a comet C/2020-F3 animation, RCM satellites, an exoplanet concept.
- Dataset record: Open Government Licence - Canada, FITS, published 2018-10-16, record ID 62d8033b-87b6-4322-8d5f-e26bebf934c1, resources (CADC archive, FITS Image User's Guide PDF, XML metadata, tutorial).
- Tutorial: CSA FTP `ftp.asc-csa.gc.ca` under `/users/OpenData_DonneesOuvertes/pub/NEOSSAT/ASTRO/{year}/{day_of_year}/` with files `NEOS_SCI_{YYYY}{DOY}{HHMMSS}.fits` (suffixes `_cor`, `_cord`, `_clean` for processed); or **CADC via astroquery** (`Cadc().query_region(...)`, ADQL on `caom2.Plane` with `collection='NEOSSAT'` and MJD ranges, image URLs through `https://ws.cadc-ccda.hia-iha.nrc-cnrc.gc.ca/caom2ops/sync?ID=cadc:NEOSSAT/<file>&POS=CIRCLE ra dec radius`). Frames are about 1000x1000 px optical. Processing: overscan, master dark, stacking, streaklet detection, frame differencing. Figures: a raw frame with saturated bleeding stars; an "example image" with a fuzzy object; a stacked frame with an overscan stripe, a streaklet mask and a moving-object mask. **The tutorial's own result shows that differencing without drift correction flags every star as moving** (double dots), which is exactly the false positive our alignment rules must prevent.

## 7. CADC
Archive hub, text tiles only. Notice: the data are for professional astronomers and not intended for general public use. Relevant parts:
- **DSS (Digitized Sky Survey):** photographic plates, epochs about 1950 to 2002, 1.0 to 1.7 arcsec pixels, FITS or JPG for any sky position, by name or coordinates; surveys POSS-I E/O, POSS-II J/F/N, SERC, AAO, Pal-QV. Copyright notices per survey (STScI, Caltech, AAO, ROE); the exact copyright is in each FITS header. A decades-long baseline makes proper motion obvious for Barnard's Star. The programmatic DSS endpoint was not confirmed from this page (verify, for example the STScI DSS server or NASA SkyView).
- **SSOIS:** solar-system object image search by name, arc or orbital elements, with CADC, JPL Horizons or MPC ephemerides; cite Gwyn, Hill and Kavelaars (2012). Programmatic use not confirmed (verify).
- **Web services:** TAP (`argus`), SIA, SODA cutouts and DataLink (`caom2ops`), a collection list that includes NEOSSAT, UKIRT, WIRWolf stacks.

## 8. Corrections to our earlier documents
1. **"Combine the six detector arrays"** (project reference 1.5, item 7) means, in the official brief, **adding together the data of each detector separately** (per-detector co-add to raise signal-to-noise). It does not mean merging detectors or wavelengths. Implement it as a per-detector stack over a chosen time window, with alignment, and label it "stacked".
2. **QR2 is not searchable any more** and is downloadable only until February 2027. Do not build any QR2 path beyond ignoring it.
3. **A fifth collection exists:** `spherex_dr1_cube` (All-Sky Cube).
4. **EPSF zones are not always 21x21:** detector 3 has 11x41.
5. The native pixel scale is **6.15 arcsec**.
6. Briefing 01's "TAP and SIA" notes are right; **TAP returns new data first and is slow (about 20 s)**, so cache and show progress.
7. **Challenge asks for embeddable coordinate URLs**, so support an embed mode.
8. NEOSSat and CADC were marked "background only" in AGENTS.md; the team now wants them included as optional context layers after the MUST items.
